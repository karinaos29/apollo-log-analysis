# APOLLO2028 Assessment LLM

Research assistant work on **log and scenario analysis** for the APOLLO2028
healthcare business game (`nipg14.inf.elte.hu`). Focus: replacing the
platform's current templated end-of-session summary with text generated by
a locally-run foundation model from the session's JSON log.

## Background

Each session produces a JSON log and a PDF report. The PDF's current
"AI-Generated Summary" is a fixed score-to-adjective template with no
reference to specific days, events, or actions — even though the JSON
contains a rich event history and day-by-day score trajectories. The goal
is a locally-run model that generates two parts per report, matching the
platform's existing structure:

- **Descriptive part** — a neutral, factual reconstruction of what happened
  (specific days/events), from the system's point of view
- **Evaluative part** — a higher-level, always encouragingly-toned
  assessment of what the results meant

## Quick start

```bash
python3 -m venv venv && ./venv/bin/pip install -r requirements.txt
brew install ollama && ollama serve        # in a separate terminal
ollama pull phi3.5
```

```bash
# one report
./venv/bin/python3 scripts/run_hybrid_generation.py data/tutorial/apollo_player-Karina-2026-08-30T20-38-57.json phi3.5 /tmp/report
# all five test logs (canonical seed 42 -> experiments/v4/)
./venv/bin/python3 scripts/batch_hybrid.py
# repeat runs with other seeds
./venv/bin/python3 scripts/batch_hybrid.py --seeds 1 2 3 --out experiments/v4/repeats
```

Each output file contains the final report (`## Descriptive part`, `## Evaluative part`) plus the Python draft,
the validation log and the model's raw text, so every report can be traced.

## How the current pipeline (v4) works

```
session log (JSON) -> context_card.py      compute facts: balances, patients, four scores, swings, decisions
                   -> report_draft.py      Python writes the DESCRIPTIVE part (facts correct by construction)
                   -> run_hybrid_generation.py
                        model writes the EVALUATIVE part from a digit-free fact list
                        -> checks: no digits, real event names, hedged causality, 3-5 sentences
                        -> one rewrite if it fails -> deterministic template if it still fails
```

## Repository layout

| Path | What it is |
|---|---|
| `scripts/context_card.py` | computes the session facts from a log (used by v3 and v4) |
| `scripts/report_draft.py` | v4 descriptive text, evaluative checks and fallback template |
| `scripts/run_hybrid_generation.py` | v4 runner for one log (`--seed N`, optional `--rewrite-descriptive`) |
| `scripts/batch_hybrid.py` | v4 runner for all logs, with repeat seeds |
| `scripts/llm_client.py` | Ollama client and fixed decoding settings |
| `scripts/score_outputs.py`, `scripts/batch_score.py` | automatic scores (see `docs/EVALUATION_CRITERIA_v2.md`) |
| `scripts/legacy/` | v2 and v3 pipelines, kept to reproduce those experiments |
| `data/` | session logs (5 single-player logs + 1 multi-player export, not used yet) |
| `experiments/v1` … `v4` | outputs and comparison write-ups per pipeline version |
| `experiments/v4/REVIEW.md` | reading of the final and repeat outputs, with reports flagged for supervisor revision |
| `experiments/v4/BASELINE_COMPARISON.md` | our reports side by side with the platform's current summaries, plus financial-figure questions |
| `prompts/PROMPT.md` | prompt texts and open questions |
| `docs/` | evaluation criteria (v2 is current; v1 kept for reference) and model shortlist |

## Experiments

Scores below are from the current scorer applied to all versions (see `experiments/v4/COMPARISON.md`).

| Version | Input to the model | Models | Summary |
|---|---|---|---|
| [v1](experiments/v1/COMPARISON.md) | full raw JSON (64-184 KB) | Llama 3.2, Phi-3.5, Qwen 2.5 | Phi-3.5 best; groundedness 0.00-0.33 on all runs |
| [v2](experiments/v2/COMPARISON.md) | compact table + day-thirds prompt | Phi-3.5 only | factual accuracy up (0.77 -> 0.93); 60-day logs still ignore mandatory facts |
| [v3](experiments/v3/COMPARISON.md) | Python-computed context card, 2-step chain, validation + retry | Phi-3.5 only | groundedness 0.15 -> 0.34, all figures correct, 4-score coverage 1.00; some invented/scrambled details remain |
| [v4](experiments/v4/COMPARISON.md) | Python-written description + model-written evaluation checked by strict rules | Phi-3.5 only | groundedness 0.71, factual accuracy 0.99, 1 model call (~27 s); description is deterministic, model evaluation accepted in 5 of 5 runs |

The automatic scores mostly confirm that the facts are right; whether the evaluations are good is
judged by reading them (`experiments/v4/REVIEW.md`).
